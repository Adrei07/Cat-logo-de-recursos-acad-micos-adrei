# Criterios de Clasificación de Recursos Académicos

Para mantener el repositorio organizado y facilitar la recuperación de la información, cada recurso, script o dataset ingresado al catálogo debe poder clasificarse con base en los siguientes cuatro criterios:

## 1. Tipo de Recurso (Formato y Herramienta)
Define la naturaleza técnica del archivo y cómo debe ejecutarse o procesarse. Esto permite saber rápidamente si se requiere un entorno de ejecución específico.
*   **Ejemplos de clasificación:**
    *   *Código fuente / Scripts:* Archivos ejecutables de Python (`.py`), rutinas en C/C++ para microcontroladores o consultas SQL (`.sql`).
    *   *Entornos de experimentación:* Cuadernos de Jupyter (`.ipynb`) para análisis exploratorio.
    *   *Fuentes de Datos:* Archivos en bruto como `.csv` o esquemas de bases de datos relacionales.
    *   *Documentación:* Apuntes teóricos, diagramas o estructuras de desglose en Markdown (`.md`) o PDF.

## 2. Dominio o Área de Conocimiento (Tema)
Agrupa los recursos según la rama de la ingeniería, ciencia o disciplina a la que pertenecen, permitiendo filtrar el catálogo por área de estudio.
*   **Ejemplos de clasificación:**
    *   *Inteligencia Artificial y Machine Learning* (Ej. entrenamiento de modelos predictivos).
    *   *Arquitectura de Datos* (Ej. diseño de entidades y relaciones, uniones de tablas).
    *   *Electrónica y Hardware* (Ej. análisis de circuitos, leyes de voltaje/corriente).
    *   *Gestión y Planeación de Proyectos* (Ej. estándares de dirección, metodologías de trabajo).

## 3. Nivel de Complejidad o Etapa (Nivel)
Indica la madurez del recurso o la profundidad técnica requerida para entenderlo, lo cual es útil para diferenciar entre apuntes básicos y proyectos finales consolidados.
*   **Ejemplos de clasificación:**
    *   *Fundamentos:* Conceptos teóricos, sintaxis introductoria o ejercicios de prueba.
    *   *Desarrollo / Intermedio:* Pruebas de concepto (PoC), limpieza de datos o algoritmos en proceso de depuración.
    *   *Producción / Avanzado:* Pipelines completos, modelos evaluados, tableros de visualización terminados o código listo para implementarse.

## 4. Contexto de Creación (Fuente u Origen)
Establece de dónde surgió la necesidad de crear el recurso, fundamental para el control de versiones, auditoría y créditos.
*   **Ejemplos de clasificación:**
    *   *Desarrollo Académico:* Proyectos finales, entregables de asignaturas o prácticas de laboratorio universitario.
    *   *Iniciativa Personal:* Scripts de automatización propios o entornos creados para investigación autodidacta.
    *   *Referencia Externa:* Documentación oficial, librerías, estándares de la industria o diagramas adaptados de repositorios de terceros (ej. GitHub).
